# Responsible AI Documentation

This document provides a transparent, honest account of OrbitalGuard AI's capabilities, limitations, and ethical commitments.

---

## 1. What This System Is — and Is Not

### What It Is

OrbitalGuard AI is a **statistical scoring prototype** for mission-critical network monitoring. It:

- Computes reproducible statistical scores (z-scores, rolling means, rolling standard deviations, piecewise risk bands, weighted composition) from telemetry data.
- Retrieves approved operating procedures from a curated Knowledge Base using vector similarity search.
- Generates explainable summaries and root-cause analyses via IBM watsonx Granite models, grounded in retrieved evidence.
- Provides decision support for human operators managing network incidents.

### What It Is Not

- **Not a trained machine-learning classifier**. There is no opaque neural network behind the core scoring values. Every prediction output is deterministically reproducible from the telemetry window in memory.
- **Not a real infrastructure controller**. The system does not possess the ability to make configuration changes, restart equipment, or alter network state.
- **Not affiliated with ISRO or any government space agency**. All operational context is synthetic.
- **Not a replacement for human judgement**. All mitigation actions require explicit human approval.

## 2. AI Model Usage

### IBM watsonx Granite Models

| Aspect              | Detail                                                   |
|---------------------|-----------------------------------------------------------|
| Models Used         | `ibm/granite-4-h-small` (primary), `ibm/granite-3-8b-instruct` (fallback) |
| Provider            | IBM watsonx.ai                                            |
| Temperature         | `0` (deterministic — same input produces same output)    |
| Max Output Tokens   | 256                                                       |
| Purpose             | Summarisation, root-cause narratives, operator checklists |
| Data Sent           | Retrieved Knowledge Base chunks + incident context only   |

### What Data Is Sent to External Services

- **Only** retrieved Knowledge Base passages and incident context are sent to IBM watsonx.ai.
- **No raw telemetry** is sent to external AI services in core functionality.
- The Edge Function truncates all context to 10,000 characters maximum before transmission.

### What Data Is NOT Sent

- User credentials or passwords.
- Raw database records.
- Other users' data.
- Service-role keys or internal configuration.

## 3. Grounding and Hallucination Prevention

### Retrieval-Augmented Generation (RAG)

The system implements strict grounding controls:

1. **Context-only responses**: The AI model is prompted to answer **only** based on provided context. The system prompt explicitly states:
   > "Base answers on the provided Context if available. Do not invent telemetry, risks, incidents or procedures."

2. **No-evidence fallback**: When no Knowledge Base documents match a query (in `grounded_explanation` mode), the system returns a safe refusal **without calling the AI model**:
   > "No relevant approved procedure was found in the current Knowledge Base."

3. **Source citations**: Every grounded response includes the source documents used, with similarity scores and metadata, allowing operators to verify the basis of any recommendation.

4. **Human approval requirement**: The AI model is prompted to always state that operational recommendations require human approval.

## 4. Honest Limitations

### No Performance Metrics Displayed

- **No ROC-AUC, precision, recall, F1, or accuracy** is displayed because no labelled evaluation dataset has been processed.
- The system honestly states this limitation on the Responsible AI page (`/console/responsible-ai`).

### Sustainability Values Are Estimates

- All sustainability metrics shown on the Sustainability page (`/console/sustainability`) are **calculated estimates** from configurable assumptions — not measured facts.
- Assumptions are visible and editable; recalculation is immediate.

### Low-Confidence Acknowledgement

- When confidence or data quality is low, the system explicitly states this instead of producing a confident-looking guess.
- Predictions include a `dataQuality` indicator alongside the risk score.

### Demonstration Data

- All demonstrations use **synthetic data** generated by a client-side simulation engine.
- Synthetic data does not represent any real network's behaviour, capacity, or operational history.

## 5. Human Control

### Decision Authority

- **Recommended actions are advisory only**. The AI system recommends; authorised human personnel decide and act.
- Corrective configuration changes that may interrupt traffic require **Operations Manager approval**.
- The system records:
  - The recommendation provided.
  - The decision made.
  - The approver's identity.
  - The timestamp of the decision.

This audit trail ensures the reasoning behind every action can be reviewed later.

### No Fully Autonomous Action

- The AI model cannot:
  - Modify device configurations.
  - Resolve incidents without human approval.
  - Escalate its own privileges.
  - Bypass workflow controls.

## 6. Explainability

### Transparent Scoring

Each prediction provides:
- **Contributing factors** with individual risk values and weights.
- **Z-scores** and rolling averages behind each telemetry metric.
- **Ranked root-cause hypotheses** with supporting evidence.
- **Confidence level** and **data quality** indicators.
- **Prediction horizon** (time window for the forecast).

### Reproducibility

- Weights are visible and editable; recalculation is immediate.
- Temperature is set to `0` for deterministic inference — the same input produces the same output.
- The statistical scoring engine uses no randomness; outputs are fully deterministic from the input telemetry window.

## 8. Accountability

### Audit Trail

All AI interactions are logged in the `ai_audit_logs` table:
- `user_id` (derived from verified JWT — not client-supplied)
- `mode` (type of AI invocation)
- `success` (whether the invocation succeeded)
- `model_id` (which Granite model was used)
- `grounded` (whether the response was grounded in retrieved evidence)
- `sources_used` (number of Knowledge Base chunks used)
- `duration_ms` (response time)

### Immutable Logs

- Audit logs are **append-only**. Updates and deletions are blocked for all application users, including administrators.
- Only the Edge Function (via service-role credentials) can insert audit records.

### Rate Limiting

- Per-user rate limits (20 requests per tumbling window) prevent abuse of AI resources.
- Rate-limit state is stored server-side and cannot be reset by users.
